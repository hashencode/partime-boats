## Debug Summary

预期：删除筛选所得的最后一条账号，空态出现后，第一次点击“重置筛选”即可清空筛选并重新加载列表。

旧版本的可重复步骤：

1. 通过 UI 新增一条专用测试查询账号，按完整账号名筛选，仅保留该行。
2. 点“删除”，再确认“删除账号”。
3. 空态及“重置筛选”出现后立即点击，不额外等待弹窗消失。

两次有效立即点击均失败（2/2）：输入框仍保留账号名。按钮中心点的 `document.elementFromPoint` 命中 `.ant-modal-wrap`；遮罩仍为 `display:block`、`pointer-events:auto`，一次还明确读到 `dialogCount=1`。其中一次使用实际坐标点击排除了单纯定位器重试的影响。等待确认框隐藏的两次对照操作均成功（2/2）。另一次诊断准备失败，没有发生立即点击，不计入复现次数。

因果链：旧实现 `onOk` 内删除完成就广播刷新 → HTTP 读回空结果 → 空态按钮出现，但 Ant Design 仍在执行弹窗退出动画 → 遮罩接收本应落到按钮的点击。证据不支持重置筛选控制器本身失效。

## 最小修复

- `msk-account-list-page.tsx`：删除成功时仅标记 `shouldRefresh`；在该确认框 `afterClose` 中执行原有末页回退和广播刷新。取消或删除请求失败不设置该标记。
- 保留现有入口、权限、字段、主题、列宽、导出范围及接口协议。没有调整全局遮罩、动画或增加等待定时器。
- `msk-account-list-page.test.tsx`：在现有删除测试中补充取消关闭完成后不发起删除、不额外刷新两个断言。
- `msk-account-management.browser.test.tsx`：新增开启真实弹窗动画的回归用例，检查空态按钮中心是否真正可点击，再点击并确认筛选清空。

浏览器回归先在旧代码上失败于按钮命中断言（`expected false to be true`），随后同一测试在修复后通过。测试只将刷新广播替换成确定性交付的本地测试通道，HTTP 使用适配器；真实动画及 DOM 命中检测保留。因此真实 HTTP、原生广播的验证以以下实际 UI QA 为准。
