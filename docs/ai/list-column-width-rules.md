# 列表列宽测量规则

## 1. 适用范围

- 适用于后台列表页中的**非操作列**宽度校准。
- 操作列（如 `操作`、`下单`）不使用本规则，继续按独立固定宽度口径计算。

## 2. 目标

- 优先保证表头与正文内容**单行显示**。
- 允许横向滚动，但禁止通过把列压到临界宽度来换取“看似不滚动”。
- 列宽必须尽量适配**当前列表前 20 条数据中至少 90% 的情况**。

## 3. 强制规则

### 3.1 样本数

1. 默认以**当前筛选结果前 20 条数据**作为测量样本。
2. 若当前分页条数 `< 20`，先将分页切到**当前控件中最小的 `>= 20` 的页大小**后再测量。
3. 若列表是虚拟滚动表格，只渲染可视区内容，必须通过滚动虚拟容器收集前 20 条唯一行。
4. 若当前列表无数据，必须**停止计算并明确告知用户“当前列表无数据，无法执行列宽测量”**。

### 3.2 非操作列宽度经验

1. 宽度测量对象：
   - 表头文本宽度
   - 当前列表前 20 条数据中该列正文文本宽度
2. 正文文本宽度取**前 20 条样本的 90 分位值**，而不是取平均值。
3. 非操作列最终宽度公式：

```text
最终宽度 = min(
  220px,
  向上取整到 8px 的倍数(
    max(表头单行文本宽度, 正文文本宽度P90)
    + 单元格左右 padding
    + 16px 安全余量
  )
)
```

4. `16px` 安全余量必须在**文本宽度之外**单独增加，不能把它和文字本身宽度混算。
5. 单元格左右 padding 必须显式计入，不能假设“列宽就是文本可用宽度”。
6. 若当前前 20 条样本中该列**有值样本不足 2 条**，禁止根据空值结果缩窄现有列宽；此时应保持当前宽度或使用更保守经验值。
7. 最终列宽不得超过 `220px`，即使“向上取整到 8px 的倍数”后也不能突破该上限。

### 3.3 表头约束

1. 非操作列表头默认应按单行校准。
2. 若列标题仍发生换行，应优先放宽该列，不要通过保留 `break-word` 继续压缩。
3. 操作列表头不受本规则约束，可保持独立布局。

## 4. 页面测量流程

### 4.1 打开页面

1. 在本地开发环境先访问 `/login`。
2. 若当前环境仍需要登录，使用用户已确认的开发账号进入；本项目当前本地环境已确认可使用：
   - 账号：`1`
   - 密码：`1`
3. 登录后进入目标列表页，例如：
   - 订单管理：`/order-list`

### 4.2 获取元素

优先使用真实浏览器环境（如 Playwright），不要只看源码静态估算。

- 表头单元格：
  - `.ant-table-thead th`
- 虚拟滚动表格的虚拟容器：
  - `.ant-table-tbody-virtual-holder`
- 虚拟滚动表格的可见行：
  - `.ant-table-tbody-virtual-holder-inner .ant-table-row`
- 普通表格行：
  - `.ant-table-tbody > tr.ant-table-row`
- 行主键：
  - `data-row-key`

### 4.3 虚拟滚动表格收集前 20 条数据

1. 先读取当前可见行。
2. 以 `data-row-key` 去重。
3. 向下滚动 `.ant-table-tbody-virtual-holder`。
4. 每次滚动后重新读取可见行并继续去重。
5. 直到收集到前 20 条唯一行，或已滚到当前页末尾。

## 5. 宽度测量实现口径

### 5.1 推荐方式

- 在真实浏览器页面上下文中使用 `canvas.getContext('2d')` 和 `measureText(...)` 测量文本宽度。
- 字体必须使用当前页面真实字体配置：
  - `fontWeight`
  - `fontSize`
  - `fontFamily`

### 5.2 为什么不能只看 DOM 当前宽度

- 当前 DOM 宽度可能已经被旧列宽压缩过。
- 文本是否换行会受：
  - 字体
  - `padding`
  - `white-space`
  - `overflow-wrap`
  - 当前列宽
  共同影响。
- 只看“现在这一列多宽”会把已有错误继续带入下一轮计算。

## 6. 验证要求

1. 应用新宽度后刷新页面。
2. 验证非操作列表头保持单行。
3. 验证前 20 条样本中，至少 90% 的单元格在该列下不出现意外换行。
4. 若发现刚好卡边的情况，优先增大该列经验值，不要把宽度压回临界值。
